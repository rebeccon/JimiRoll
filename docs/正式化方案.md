# FastSeedRoll 正式化方案

> 审计时间：功能验证通过之后（储备池循环、种子框填充、内存稳定均已实测）
> 当前规模：11 个 .cs，约 1900 行；1 个 .cmd；无 UI、无测试、无 git

---

## 一、先说结论：当前版本"能用"，但有 4 类"实验室痕迹"

| 类别 | 问题 | 严重度 |
|---|---|---|
| **硬编码绝对路径** | 4 处写死 `D:\steam\...` | 🔴 换机/换盘直接废 |
| **硬编码游戏版本** | `0.111.0` 写死 | 🔴 游戏更新后行为未知 |
| **反射过多** | 350 行的 `Rt2Binding` 几乎全是反射 | 🟡 改个名就静默失效 |
| **工程配置缺失** | 无 git / LICENSE / CHANGELOG / 打包脚本 | 🟡 没法发布维护 |

下面按"该先做什么"排序。

---

## 二、🔴 第一优先：干掉硬编码（半天）

### 2.1 四个写死的路径

```
GameInterop.cs:23   @"D:\steam\...\data_sts2_windows_x86_64\sts2.dll"
Rt2Binding.cs:97    @"D:\steam\...\workshop\content\2868840\3755166888\RolltheSpire2\RolltheSpire2.dll"
FastSeedRoll.csproj:20  <GameDir>D:\steam\steamapps\common\Slay the Spire 2</GameDir>
FastSeedRoll.csproj:22  <Rt2Dir>D:\steam\...\RolltheSpire2</Rt2Dir>
```

**为什么这是最严重的**：我这个 mod 是**跑在游戏进程里**的，所以它根本不需要知道自己在哪 ——
游戏自己就在那儿。硬编码路径会导致：换台机器、Steam 库换盘、创意工坊编号变了 → 整个 mod 失效。

**怎么改**：

```csharp
// GameInterop.cs —— 不要从磁盘找 sts2.dll，直接用已经加载好的
// 之前写 Assembly.LoadFrom(@"D:\steam\...\sts2.dll) 完全没必要
var gameAsm = typeof(MegaCrit.Sts2.Core.Random.Rng).Assembly;   // 编译期就引用着
```

```csharp
// Rt2Binding.cs —— 不要猜 RT2 的磁盘路径
// 它由游戏 Mod 加载器载入，直接从已加载程序集里找
_rt2 = AppDomain.CurrentDomain.GetAssemblies()
        .FirstOrDefault(a => a.GetName().Name == "RolltheSpire2");
// （现有的兜底 LoadFrom 可以保留，但应基于「游戏 mods 目录」推导，而不是写死 D 盘）
```

```xml
<!-- csproj —— 改成可由环境变量覆盖，且默认值不要写死盘符 -->
<GameDir Condition="'$(GameDir)' == ''">$(STS2_GAME_DIR)</GameDir>
<!-- 或者干脆去掉：HintPath 引用是编译期需要，发布出去的 dll 不依赖它 -->
```

> **关键认识**：csproj 里的路径只影响**编译**，不影响**运行**。
> 所以发布出去的 mod 包里不该有任何盘符。运行时那份路径必须删掉。

### 2.2 写死的游戏版本

```csharp
Rt2Binding.cs:187   const string GameVersion = "0.111.0";
```

这个版本号同时用于 `GameVersionDetection` 和 `CaptureRuntimeReadOnly`。
游戏一更新（0.112），它会**照着旧版本构造快照** —— 可能悄悄算错，这是最坏的情况（给你错的种子）。

**怎么改**：从游戏自己读。STS2 有版本信息（`release_info.json` / Godot 的 `ProjectSettings` /
游戏的 version 常量）。可用的入口：

```powershell
& "_tools\probe.ps1" members "Version"          # 找游戏自己的版本常量/属性
& "_tools\probe.ps1" --rt2 members "Detect"     # RT2 怎么探测版本的
```

RT2 里有个现成的：`RolltheSpire2.Compatibility.RuntimeProfileRegistry.Resolve(string normalizedGameVersion)`
和 `GameVersionDetection.NotDetected` —— 说明 RT2 自己有"探测"流程。
**正式版应该复用 RT2 的探测结果**（比如从它持久化的 `search_environment.json` 读
`GameVersionIdentity`），而不是自己写死。

**降级策略**：读不到版本 → **明确报错并停止搜索**，绝不猜。

## 三、🟡 第二优先：把反射改成强类型（1~2 天）

`Rt2Binding.cs` 350 行里绝大多数是反射。但 **csproj 里已经引用了 `RolltheSpire2.dll`**，
所以这些都可以改成编译期强类型引用 —— 而编译器的价值正是"**改错了编译不过**"。

具体可改的（全部已用探针核实过签名）：

```csharp
// 现在（反射）                                  →  正式版（强类型）
AppDomain...GetType("...BaseGameModelKeys+Relics") →  BaseGameModelKeys.Relics.NeowsBones
Reflect.GetMember(choice, "BonesOutcome")          →  choice.BonesOutcome
_predict.Invoke(null, ...)                          →  RuntimeProfileRegistry.Predict(det, req)
Reflect.Construct(_keySetFilter, dict)              →  new ModelKeySetFilter(any, all, ban)
```

**为什么值得做**：
- 现在如果 RT2 改了字段名，代码会**静默返回 false**（只有 `_warned` 那条日志会提示）
- 改成强类型后，**编译不过** → 你立刻知道要改哪里

**保留反射的地方**（合理）：
- `NCustomRunScreen._seedInput` —— 那是**游戏的私有字段**，没有公开访问方式，只能反射。
  但应该保留"取不到就跳过"的防御。

**要加的一道保险**：启动时做一次"契约自检" —— 用已知种子跑一遍判定，
和 RT2 自己的 UI 对一次结果。不一致就报警。这样 RT2 更新后你能立刻发现。

## 四、🟡 第三优先：工程配置（半天）

### 4.1 git 仓库

```
FastSeedRoll/
├── .gitignore            bin/ obj/ *.user
├── LICENSE               选一个（MIT 最简单）
├── CHANGELOG.md          记录每个版本改了什么
├── README.md             ★ 现在的 README-zh.txt 改成 Markdown
├── src/                  把 .cs 挪进来
├── FastSeedRoll.json     manifest
└── build.ps1             一键打包
```

**注意**：现在的 `README-zh.txt` 是 UTF-8 无 BOM，记事本可能认错。Markdown 更好。

### 4.2 文件名别用中文

`开关.cmd` 这种名字在压缩、传到别的机器、非中文系统上容易出问题
（我们已经被 `.cmd` 编码坑过一次了）。建议改成 `Toggle.cmd`，
中文说明留在 README 里。

### 4.3 版本号单一来源

现在版本号散落在 `csproj`、manifest、日志里。应该：
- csproj 的 `<Version>` 作为唯一来源
- 打包脚本自动把它写进 manifest

### 4.4 一键打包脚本

```powershell
# build.ps1：编译 → 生成 manifest → 打包成 zip → 可直接拖进 Mods 目录
```

### 4.5 配置外部化

现在改条件要**重新编译**。正式版应该：

```
%APPDATA%\SlayTheSpire2\FastSeedRoll\settings.json
{
  "reserveCapacity": 15,
  "minUnknownRooms": 12,
  "requireExact": false,
  "character": "CHARACTER:SILENT",
  "ascension": 10,
  "maxRunMinutes": 3,
  "workerCount": 1
}
```

启动时读，文件不存在就写一份默认的。**注意别过度设计** ——
条件里的"遗物 = 羊毛剪 + 新叶"这种仍然是代码常量最好（改的人少，改错代价大）。

## 五、🟢 第四优先：用户体验（要做，但可以后置）

### 5.1 游戏内 UI

现在所有信息都靠日志和文件 —— 对玩家不友好。可以做一个**很小的**面板：
- 显示储备数量（13/15）
- 显示队首种子
- 一个手动"补种子"按钮
- 一个"复制全部种子"按钮

**别做 RT2 那种大编辑器** —— 那正是我们要简化的东西。

### 5.2 本地化

现在日志全是中文硬编码。正式版应该走游戏的本地化系统（`LocString`），
至少出中英两份。

### 5.3 mod 图标 + 描述

manifest 里补 `description`（现在有）、加图标。创意工坊页面需要截图。

### 5.4 日志分级

现在 `SeedStore.Log` 什么都写。正式版应该：
- `INFO` 关键事件（启动、取走、储备满）
- `WARN` 可恢复的问题
- `ERROR` API 失效
- 并且支持关掉（避免刷盘）

## 六、🟢 第五优先：发布

### 6.1 打包结构

```
FastSeedRoll-v1.0.0.zip
├── FastSeedRoll.dll
├── FastSeedRoll.json      （version 与 dll 一致）
├── FastSeedRoll.pdb       （可选，排错用）
└── Toggle.cmd
```

### 6.2 发布前必须做的验证

1. **换一台机器/换盘符测试** —— 验证没有残留硬编码
2. **游戏更新到新版本后测试** —— 验证降级路径
3. **RT2 更新后测试** —— 验证反射/契约自检
4. **全新安装测试** —— 删掉 `%APPDATA%` 下的数据目录，从零开始
5. **并发场景** —— 一边搜索一边打一整局，看内存和帧率

### 6.3 manifest 要注意的

```json
{
  "id": "FastSeedRoll",          // 一旦发布就别改，改了等于换了个 mod
  "min_game_version": "0.111.0",  // 要跟着实际测过的最低版本走
  "has_pck": false,               // 纯代码
  "affects_gameplay": false,      // ★ 保持 false：我们不改游戏规则
  "dependencies": [{ "id": "RolltheSpire2" }]   // ★ 要写明版本约束
}
```

`dependencies` **建议加上版本要求** —— 现在我们完全依赖 RT2 的内部 API，
它一改成我们的反射就废。写上约束，加载器会帮我们拦住不兼容的组合。

## 八、一句话总结

> 现在这个 mod **功能是好的、逻辑是对的、防御是到位的**，
> 但它身上有"在我机器上跑得通"的痕迹 —— 主要就是**写死的路径和版本**。
> 把那两样换掉（半天），再加上 git / LICENSE / README / 打包脚本（半天），
